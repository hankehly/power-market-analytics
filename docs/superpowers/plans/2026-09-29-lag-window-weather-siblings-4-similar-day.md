# Lag-Window Weather Siblings, Part 4: The Similar Days — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `ftr_period_similar_day` the weather its three pool days had at the period's hour, their inverse-distance mean under the job's own rule, and each one's difference from D's forecast: 16 columns, 8 per element.

**Architecture:** The mart stays one row per scoring run and period; it gains three left joins to `fct_area_weather_hourly` on the stored `similar_day_pool_rank<r>_reference_date` at the hour containing the period and one to `ftr_hour_msm` for D's forecast. The inverse-distance mean is one dbt macro, `inverse_distance_mean`, that the mart uses for both elements and a singular test applies to the stored rank loads and distances to reproduce `wavg_similar_day_pool_top3_demand_kwh` — the proof that the SQL weights are the job's. `available_at` and `published_at` are unchanged: the row already waits for the vintage, and a reference day's weather is public an hour after its hour.

**Tech Stack:** dbt 1.12 (Spark adapter, unit tests, singular tests, macros), Feast views generated by `scripts/generate_feature_views.py`, the pytest fixture in `tests/conftest.py`.

**Spec:** `docs/superpowers/specs/2026-09-29-lag-window-weather-siblings-design.md`, section 5.7 and decisions 9, 10 and 11; the naming guide `docs/Feature-Naming.md`. PRs 1–3 (#239, #240, #241) are merged.

## Global Constraints

- Every feature column carries `meta.feature: true`, `meta.categorical: false` and a `meta.expression` from the spec's table, unique across the marts; physical names as spec 5.7 spells them.
- No `avg()` or `sum()` over doubles: every sum is explicit, in rank order, so a rebuild gives the same bit (CLAUDE.md, dbt rules).
- A numeric literal with a decimal point is `decimal` in Spark SQL: write `cast(1 as double) / d`, never `1.0 / d`.
- The job's rule, verbatim (`tasks/demand/similar_day.inverse_distance_weights` and `similar_day_feature._weighted_mean`): `inv_r = 1 / d_r` over the ranks present; if any present rank has `d_r = 0`, `inv_r = 1` for those and `0` for the rest; `total = ((inv_1 + inv_2) + inv_3)`; `w_r = inv_r / total`; `mean = ((w_1 x_1 + w_2 x_2) + w_3 x_3)` with an absent rank contributing nothing; null when no rank is present. "Present" for a weather sibling means the value is present (spec 5.7: "over the ranks whose value is present").
- Hour containing the period: `cast(div(time_code + 1, 2) as int)`.
- `available_at` and `published_at` of `ftr_period_similar_day` are unchanged (spec 5.7, section 6).
- Proof recipes as in PRs 1–3: a scratch copy before the build, a null-safe full-outer-join diff after, a Feast read-through, all in the devcontainer's own Spark session (`scratch/2026-09-29-weather-siblings-daytype-window/run_sql.py`; the thriftserver stalls on aggregates).
- Commits Conventional with the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. A rank whose reference day has no fact hour drops from the mean and the weights renormalise over the ranks with a value; the load columns and `wavg_similar_day_pool_top3_demand_kwh` are untouched (Task 2's unit test, row C).
2. A zero distance: the zero-distance ranks share the weight equally and the others get 0 (Task 2's unit test, row D).
3. A pool of fewer than three days (rank 2 and 3 reference dates null): the mean over the ranks present (Task 2's unit test, row E).
4. A day without a forecast row: siblings present, deltas null, `available_at` unchanged (Task 2's unit test, row F).
5. The macro applied to the stored rank loads reproduces the job's `wavg_similar_day_pool_top3_demand_kwh` on every warehouse row (Task 1's singular test; the tolerance is measured before it is pinned).

**Files:**

- Produces: `{{ inverse_distance_mean(values, distances) }}` — `values` and `distances` are lists of three SQL expressions (rank order); returns one double expression.

- [ ] **Step 1: Write the macro**

```sql
{% macro inverse_distance_mean(values, distances) -%}
{#- The similar-day job's inverse-distance weighted mean over the ranks whose value
    is present (tasks/demand/similar_day.inverse_distance_weights and
    similar_day_feature._weighted_mean): inv_r = 1 / d_r; when a present rank has
    d_r = 0, those ranks take inv 1 and the others 0; total = inv_1 + inv_2 + inv_3
    in rank order; w_r = inv_r / total; the mean adds w_r x_r in rank order, an
    absent rank contributing nothing; null when no rank is present. -#}
{%- set present = [] -%}
{%- for i in range(values | length) -%}
  {%- do present.append('(' ~ values[i] ~ ' is not null and ' ~ distances[i] ~ ' is not null)') -%}
{%- endfor -%}
{%- set any_zero = [] -%}
{%- for i in range(values | length) -%}
  {%- do any_zero.append('(' ~ present[i] ~ ' and ' ~ distances[i] ~ ' = 0)') -%}
{%- endfor -%}
{%- set inverse = [] -%}
{%- for i in range(values | length) -%}
  {%- do inverse.append(
    '(case when not ' ~ present[i] ~ ' then cast(0 as double)'
    ~ ' when (' ~ any_zero | join(' or ') ~ ') then (case when ' ~ distances[i] ~ ' = 0 then cast(1 as double) else cast(0 as double) end)'
    ~ ' else cast(1 as double) / ' ~ distances[i] ~ ' end)'
  ) -%}
{%- endfor -%}
{%- set total = '(' ~ inverse | join(' + ') ~ ')' -%}
{%- set terms = [] -%}
{%- for i in range(values | length) -%}
  {%- do terms.append('coalesce((' ~ inverse[i] ~ ' / ' ~ total ~ ') * ' ~ values[i] ~ ', cast(0 as double))') -%}
{%- endfor -%}
case when {{ total }} = 0 then cast(null as double) else ({{ terms | join(' + ') }}) end
{%- endmacro %}
```

- [ ] **Step 2: Write the singular test**

```sql
-- The similar-day job's mean rule, applied by the inverse_distance_mean macro to the
-- stored pool rank loads and distances, must give the job's own
-- wavg_similar_day_pool_top3_demand_kwh: the proof that the weather siblings of
-- ftr_period_similar_day carry the job's weights (spec
-- 2026-09-29-lag-window-weather-siblings, section 8). The rank loads are the hourly
-- loads halved and the job halves after summing; halving is exact in binary, so the
-- two agree to the bit (measured on the first build: see the plan).
select
  similar_day_run_id,
  area_code,
  trade_date,
  time_code,
  wavg_similar_day_pool_top3_demand_kwh,
  {{ inverse_distance_mean(
    ['similar_day_pool_rank1_demand_kwh', 'similar_day_pool_rank2_demand_kwh', 'similar_day_pool_rank3_demand_kwh'],
    ['similar_day_pool_rank1_distance', 'similar_day_pool_rank2_distance', 'similar_day_pool_rank3_distance']
  ) }} as rule_mean
from {{ ref('ftr_period_similar_day') }}
where similar_day_pool_rank1_demand_kwh is not null
  and not (wavg_similar_day_pool_top3_demand_kwh <=> {{ inverse_distance_mean(
    ['similar_day_pool_rank1_demand_kwh', 'similar_day_pool_rank2_demand_kwh', 'similar_day_pool_rank3_demand_kwh'],
    ['similar_day_pool_rank1_distance', 'similar_day_pool_rank2_distance', 'similar_day_pool_rank3_distance']
  ) }})
```
